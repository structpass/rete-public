# rete 業務シナリオ一覧（シナリオテスト基盤）

> このファイルは rete の業務シナリオを**シナリオテスト**用に網羅列挙した正本の入口（index）です。
> 目的は「デザインや挙動の機微」ではなく **「そもそも通るか／想定できているか」** を確認すること。
> 副次目的として、期待結果が書けない箇所＝**仕様未確定**を炙り出して仕様課題を発見します。

> **世界観バイブル**: 登場ロール・実在キャスト（18名）・利用シーン（時間軸イベント）は [`cast-and-scenes.md`](./cast-and-scenes.md) に定義。
> 本 index の各シナリオは、抽象「ADMIN／一般ユーザー」を**そのキャストへ再キャスト**して具体化する（順次反映）。
> rete・struct-pass-reference（WMS）・instruction-board の3システム横断で、権限境界・他者とのコミュニケーション・誤操作・運用イベントを網羅する。

---

## この文書の使い方

### 形式

各シナリオは Gherkin/BDD を簡約した **`前提（Given）／操作（When）／期待結果（Then）`** で書きます。
安定したシナリオは `e2e/features/*.feature`（日本語キーワード `機能/シナリオ/前提/もし/かつ/ならば`）に昇格させ、Playwright で E2E 自動化します（**本 index はその元ネタ**）。運用の正本は [`e2e/README.md`](../../e2e/README.md)。

> ロードマップ: **洗い出し（本ファイル）→ `.feature` 化 → E2E 自動化 → 再帰テスト**。
> 一気に作り込まず、要素をピックして少しずつ繋げる方針。`.feature` 化・E2E は別チケットで後続。

### 状態凡例（status）

| 記号 | 意味                            |
| ---- | ------------------------------- |
| ⬜   | unverified（未確認・初期値）    |
| ✅   | passing（通ることを確認済み）   |
| ❌   | failing（通らない／不具合あり） |

> 状態追跡は**後付け**の層です。初期は全シナリオ ⬜。`.feature`/E2E 化したら CI 結果や本表の更新で状態を埋めていきます。

### 仕様未確定マーカー

| 記号 | 意味                                                                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ⚠    | **仕様未確定** — 「ならば（期待結果）」を断定で書けなかった箇所。実装挙動が想定されているか要確認。仕様課題の候補（[§ 仕様未確定一覧](#-仕様未確定一覧副次目的の収穫) に集約） |

⚠ は status（通る/通らない）とは**直交**します。「通るかどうか以前に、正解が何か決まっていない」を表します。

## メンテナンス指針

- **シナリオ追加**: 新機能を作ったら、まずここに `前提/操作/期待結果` を 1 行足す（`.feature` より先・軽量）。
- **期待結果が書けない時**: 無理に断定せず ⚠ を付け、上の一覧に転記する（仕様課題の発見が目的）。
- **`.feature` 化**: 安定したトラックから `e2e/features/*.feature` へ昇格（運用正本 = [`e2e/README.md`](../../e2e/README.md)）。本 index はカタログとして残す。
- **状態更新**: E2E 化後は CI 結果に合わせて status 列（⬜/✅/❌）を更新する。
