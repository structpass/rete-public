## ログイン・認証（P2-1 / P2-2）

### P2-01 通常ログイン（MFA未設定の倉庫担当が朝イチで入場）

- **登場**: 鈴木一郎（物流センター 入荷担当・倉庫オペレーター・MFA未設定）
- **システム**: rete auth
- **前提(Given)**: 鈴木のアカウントは有効（`Account.isActive=true`）・MFA未設定。テナントの MFA 強制は**この時点ではまだ未適用**（強制適用は P2-05 で扱う）。
- **操作(When)**: `/login` でメールアドレス `suzuki@marusan.co.jp` とパスワードを入力して送信する。
- **期待結果(Then)**:
  - 認証成功・セッション確立し `/hub` へ遷移、ハブのダッシュボードが表示される
  - MFA 未強制のため TOTP 入力ステップは挟まれない
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)
- 対応: S-AUTH-01

### P2-02 MFA 2段階ログイン（事務主任が TOTP で入場）

- **登場**: 伊藤千夏（業務管理部 主任・事務管理者・MFA有効・OF_ADMIN）
- **システム**: rete auth
- **前提(Given)**: 伊藤は MFA 有効（TOTP 登録済）。スマートフォンの認証アプリが手元にある。
- **操作(When)**: `/login` でメール＋パスワード認証 → 続く MFA チャレンジ画面で認証アプリの 6 桁コードを入力する。
- **期待結果(Then)**:
  - パスワード段で partial session、TOTP 検証成功で full session に昇格し `/hub` へ遷移
  - 誤った 6 桁コードでは full session に昇格せず、再入力を促す
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)
- 対応: S-AUTH-02

### P2-03 バックアップコードでログイン（端末機種変で TOTP が使えない）

- **登場**: 中村彩（情報システム室 担当・事務管理者・MFA有効・SYS_ADMIN）
- **システム**: rete auth
- **前提(Given)**: 中村は MFA 有効。スマホを機種変更し認証アプリの TOTP がまだ移行できていないため、MFA セットアップ時に控えたバックアップコードを使う。
- **操作(When)**: パスワード認証後の MFA チャレンジで「バックアップコードを使う」を選び、未使用のバックアップコード 1 本を入力する。
- **期待結果(Then)**:
  - ログイン成功・full session 確立し `/hub` へ
  - 使用したバックアップコードは**消費されて無効化**され、同じコードでの再ログインは失敗する
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)
- 対応: S-AUTH-03

### P2-04 連続ログイン失敗（throttle 429 ＋ アカウントロックアウト）

- **登場**: 三田誠（ベーカリー三田 店主・顧客・閲覧専用・MFA未設定）
- **システム**: rete auth
- **前提(Given)**: 三田は #高崎CK受発注 とは別の小口顧客で、たまにしか rete を開かずパスワードをうろ覚え。`/login` で誤ったパスワードを連打する。
- **操作(When)**: 短時間（60秒内）に誤パスワードで 6 回連続ログイン試行する。さらに 15 分以内に閾値（5回）を超えて失敗を重ねる。
- **期待結果(Then)**:
  - レート制限層: 60秒内で 5 回を超えた試行は **429（ブルートフォース抑制）** で弾かれる
  - アカウント保護層: 短時間に 5 回連続失敗するとアカウントが**一時ロックアウト**され、正しいパスワードを入れても認証されない（401/ロック応答）
  - ⚠ ロック解除の経路（15分自動解除か／管理者による明示解除のみか）と、ロック中であることを利用者へ伝える文言・問い合わせ導線が**未定義**（throttle=60秒レート制限 と lockout=5回/15分 の二層がどう協調するかも明文化されていない）
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: ロック解除フロー・利用者への通知文言・throttleとlockout二層の協調が未定義。S-AUTH-09 はレート 429 のみ言及、解除は P6-1 で未定義)
- 対応: S-AUTH-09

### P2-05 MFA強制下・未設定者の強制設定誘導（入荷担当の初回ハマり）

- **登場**: 鈴木一郎（物流センター 入荷担当・倉庫オペレーター・MFA未設定）
- **システム**: rete auth / mfa
- **前提(Given)**: 高橋（情シス室長）が P0 でテナントの **MFA 強制（enforced）** を有効化済。鈴木はまだ MFA 未設定。
- **操作(When)**: 鈴木が `/login` でメール＋パスワードを送信し認証成功する。
- **期待結果(Then)**:
  - ログイン成功直後、MFA 未設定のため `/settings/login-settings`（MFA セットアップ）へ誘導され、toast で設定を促される
  - ⚠ 設定を完了せずに `/desk` 等の業務画面へ直接 URL アクセスした場合に**業務操作までブロックするか（強制 redirect で締め切るか／誘導 toast のみで素通り可能か）**が未確定
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: 強制設定が「誘導」止まりか「完了まで業務操作ブロック」かが明文化されていない)
- 対応: S-AUTH-08 ／ S-SET-04

### P2-06 MFA セットアップ完了＋バックアップコード受領（棚卸担当が初期化）

- **登場**: 山本翔（物流センター 棚卸/在庫担当・倉庫オペレーター・MFA未設定→設定）
- **システム**: rete auth / mfa
- **前提(Given)**: 山本も MFA 強制下の未設定者で、P2-05 同様に設定画面へ誘導された。
- **操作(When)**: `/settings/login-settings` で MFA setup を開始 → 表示された otpauth（QR）を認証アプリに登録 → アプリの 6 桁コードを入力して確認 → 有効化する。
- **期待結果(Then)**:
  - MFA が有効化され、以後のログインで TOTP が必須になる
  - **バックアップコードが一度だけ**画面に表示され、再表示はされない（控えるよう案内される）
  - 次回ログインから P2-02 と同じ 2 段階フローになる
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)
- 対応: S-SET-04 ／ S-AUTH-08

### P2-09 業務ロール未割当ユーザーの日常操作の壁（臨時パートの体験）

- **システム**: rete home / desk / files
- **前提(Given)**: 加藤はアカウント有効でログインはできるが、rete 業務ロール（RoleDefinition）が**未割当**。どの Space にも membership を持たない。
- **操作(When)**: ログイン後 `/hub` を閲覧し、続けて `/desk`・`/files` を開いてチャット発話・タスク作成・ファイルアップロードを試す。

- **状態**: ⬜ ／ **仕様**: ⚠(未確定: 全 false の遮断はアサート可能だが、未割当者向けの説明 UX・依頼導線の有無が未定義)

## reference（WMS）操作起点 — 入荷検品・発注・出荷（P2-4 / P2-5）

### P2-10 reference SSO 入場 → 入荷検品で予定数≠実数の差異（冷凍コロッケ 4ケース不足）

- **登場**: 鈴木一郎（入荷担当・WH_USER）、小林拓也（発注起票者・OF_USER）
- **システム**: rete↔reference（SSO）／ reference WMS
- **前提(Given)**: 小林が reference で北関東フーズへ発注（PO-2026-0412：冷凍コロッケ 段ボール **240ケース**・12/20 着便）を起票済。本日その入荷便が物流センターに到着。鈴木は rete に既存セッションを持っている。
- **操作(When)**:
  1. 鈴木が rete のハブ「システム」導線から reference へ SSO 入場する（再認証なし）
  2. reference で PO-2026-0412 に対する Receiving（入荷検品）を開始し、現品を数える
  3. 実数が **236ケース**（4ケースが輸送中破損で受領不可）だったため、検品数量を 236 と入力し差異理由「破損4ケース」を登録する
- **期待結果(Then)**:
  - rete セッションのまま reference に再認証なしで入場できる（OIDC consent 済の silent ログイン）
  - Receiving に予定240／実数236／差異-4 が記録され、**Stock(在庫)には実数236ケース分のみ**が計上される（予定数で増えない）
  - ⚠ reference 側の入荷差異が rete の #入荷検品 チャネルのタスク/お知らせへ**自動連携されるか**は未確定＝現状は鈴木が手動で rete にタスク起票して佐藤（倉庫長）・小林に共有する前提（S-DESK-03 の Backlog 連携有無と同根）
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: SSO シームレス入場と入荷差異の在庫反映はアサート可能だが、reference差異→rete タスク/お知らせの自動連携は未配線＝手動転記前提)
- 対応: S-AUTH-04

### P2-11 reference 発注（北関東フーズへ冷凍コロッケ）→ 主任が承認

- **登場**: 小林拓也（発注担当・OF_USER）、伊藤千夏（業務管理部 主任・OF_ADMIN）、高木茂（北関東フーズ 営業・Supplier として登場）
- **システム**: reference WMS ／（rete #北関東フーズ連携で前段調整）
- **前提(Given)**: 新商品「冷凍コロッケ（業務用1kg）」の初回発注。小林は事前に rete #北関東フーズ連携 で高木と納期（12/20 着便・最小ロット）を調整済。reference で高木の会社は Supplier として登録されている。
- **操作(When)**:

  2. OF_USER は起票までが権限のため、承認は伊藤（OF_ADMIN）に回付する
