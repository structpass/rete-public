# フェーズ P4 — 組織変更・人の出入り（運用イベント）

> このファイルは cast-and-scenes.md のフェーズ P4 を Given/When/Then に展開したジャーニーです。

対象シーン＝退職→アカウント停止（P4-1）／部署移動（P4-2）／プロジェクト脱退・復帰（P4-3）／新規ユーザー参加（P4-4）／事業部の追加（P4-5）／チャネルの追加（P4-6）／チャネル参加者の増減（P4-7）。
本フェーズはマルチユーザー化が**実装済み**である前提で書く（Space 可視性 enforcement・所有者チェック・添付/分類の Space 所有権チェック・assignee ドロップダウン・メンション自分宛て絞り込みは **now enforced** としてアサート）。一方、退職時の個人データ処理 / OIDC grant 失効 / SLO、事業部追加時の初期払い出しフロー、最後の ADMIN を保護するガードは**マルチユーザーとは別理由で未定義**のため ⚠ を維持する。

### P4-01 退職に伴うアカウント即時ロック（認証遮断）

- **登場**: 高橋 健一（情シス室長・システム ADMIN）／渡辺 美咲（物流センター 出荷担当・退職対象）
- **システム**: rete members / auth
- **前提(Given)**: 渡辺は #東名運輸・配車 のメンバーで、当日付で退職。渡辺は rete に有効セッションを持ち、現在ログイン中。高橋はシステム ADMIN。
- **操作(When)**: 高橋がメンバー画面（`/settings`）で渡辺の行を開き、アカウントを「ロック（isActive=false）」に切り替える。直後、渡辺が rete の任意の保護 API（例: `/desk` のチャネル一覧取得）を叩く。
- **期待結果(Then)**:
  - 渡辺の次リクエストは 401 で遮断される（`deserializeUser` が毎リクエストで DB から `Account.isActive` を引き直すため、ログアウトを待たず即時失効）。
  - 渡辺は再ログインも不可（認証段階で 401）。
  - 高橋側の members 一覧で渡辺が「ロック中」表示になる。
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)

### P4-02 退職者の所有物・他システムセッションの残存

- **登場**: 渡辺 美咲（退職・ロック済）／高橋 健一（システム ADMIN）
- **システム**: rete desk / files ／ reference（WMS）
- **前提(Given)**: P4-01 で渡辺は isActive=false。渡辺は #東名運輸・配車 に「12/15 東名運輸 4t 車1台 追加手配」タスク（担当=渡辺）と、配車表ファイル数点を残している。渡辺は退職前に reference へ SSO 入場済みで、reference 側に有効なログインセッションが残っている。
- **操作(When)**: 高橋が渡辺の残タスク・添付の扱いを確認しようとする。並行して、ロック直後に渡辺の reference セッションがまだ生きていないかを点検する。
- **期待結果(Then)**:
  - 渡辺の発話・タスク・添付レコードは削除されず残存し、システム ADMIN の高橋は `assertOwnerOrAdmin` を通過して閲覧・編集・再割当が可能。
  - ⚠ 退職者の所有物（タスク・ファイル・発話）の引き継ぎ／匿名化／削除の規定が**未定義**＝「誰に再割当するか」「個人データをどう処理するか」の正解像が無い（policy §6・ADR 0008 相当）。
  - ⚠ rete ロックは reference 側セッションを即時失効させない＝**OIDC grant 失効・SLO（単一ログアウト）が未定義**のため、渡辺の reference セッションは**TTL 自然失効まで生存**しうる（rete=IdP のロックが RP に伝播しない）。
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: 退職者の個人データ処理・OIDC grant 失効・SLO が未定義。reference 側は TTL まで生存)

### P4-03 部署移動：旧 Space を外し新 Space を付ける（可視の切替）

- **登場**: 山本 翔（物流センター 棚卸担当→業務管理部 異動）／佐藤 大輔（物流センター ORG ADMIN）／伊藤 千夏（業務管理部 ORG ADMIN）
- **システム**: rete memberships
- **前提(Given)**: 山本は物流センター ORG・在庫精度改善PJ・#棚卸差異 の membership を持つ。4月付で業務管理部へ異動。
- **操作(When)**:
  - 佐藤（物流センター ORG ADMIN）が在庫精度改善PJ／#棚卸差異／物流センター ORG から山本の membership を remove。
  - 伊藤（業務管理部 ORG ADMIN）が業務管理部 ORG と必要なチャネルへ山本を upsert で追加。
  - 山本が再ログインして desk のサイドバーを確認する。
- **期待結果(Then)**:
  - 山本のサイドバーから物流センター ORG・#棚卸差異 が**消え**、直接 URL で `#棚卸差異` を開いても 403（非メンバーには存在ごと隠れる）。
  - 業務管理部 ORG が新たに可視化され、追加されたチャネルが一覧に出る。
  - チャネル可視は親 PROJECT membership で解決されるため、在庫精度改善PJ を外した時点で配下チャネルが一括で不可視になる。
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能) ／ 対応: S-SPC-04 / S-SPC-05

### P4-04 部署移動後、旧チャネルに残した発話の所有と可視

- **登場**: 山本 翔（異動済）／佐藤 大輔（物流センター ORG ADMIN）
- **システム**: rete desk
- **前提(Given)**: 山本は異動前、#棚卸差異 に「ロット LOT-2402 棚卸差異 −12 ケース、ロケーション A-03 で要再カウント」など複数発話を残している。P4-03 で #棚卸差異 の membership は外れた。
- **操作(When)**: 山本が異動後に過去の自分の棚卸差異発話を見返そうとする。佐藤が #棚卸差異 を開き、山本の旧発話がスレッドに残っているか確認する。
- **期待結果(Then)**:
  - 発話レコード自体は削除されず #棚卸差異 のスレッドに残り、メンバーである佐藤からは引き続き読める（履歴の連続性が保たれる）。
  - 山本本人は #棚卸差異 の非メンバーになったため、自分の過去発話を含めてチャネルごと不可視（403）。
  - ⚠ 異動者が残した発話の所有（編集・削除権）の扱いが**未定義**＝本人が不可視化された後、その発話を本人が訂正したいケースの正解像が無い（所有者は山本のままだが到達できない＝孤児発話の扱い）。
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: 異動で不可視化された本人の旧発話の編集経路が未定義)

### P4-05 部署移動の下流：reference 側ロール変更（SSO 同一性は不変）

- **登場**: 山本 翔（倉庫→業務管理部）／高橋 健一（reference SYS_ADMIN）
- **システム**: reference（WMS）／ rete↔reference SSO
- **前提(Given)**: 山本は reference で WH_USER（倉庫一般・入荷/出荷/棚卸の現場作業）。異動で業務管理部の事務作業（発注・マスタ）に移るため OF_USER へ変更が必要。SSO は rete アカウント(sub)を `User.oidcSub` で引き当てる。
- **操作(When)**: 高橋が reference の管理画面で山本の UserRole を WH_USER→OF_USER に変更。山本が rete から「システム」導線で reference へ SSO 入場する。
- **期待結果(Then)**:
  - reference 側で山本は OF_USER の権限（発注書起票・マスタ更新）に切り替わり、棚卸/在庫調整系の倉庫操作は権限外になる。
  - rete アカウントの sub（oidcSub マッピング）は不変のため、SSO の同一性は維持され再連携は不要。
  - rete の業務ロール（倉庫オペレーター→事務管理者）と reference の UserRole は**独立**に更新が要る（3軸直交。片方だけ変えても他方は追従しない）。
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能)

### P4-06 プロジェクト脱退→復帰（membership remove→re-add）

- **登場**: 松本 由美（業務管理部 マスタ管理・在庫精度改善PJ MEMBER）／佐藤 大輔（在庫精度改善PJ ADMIN）
- **システム**: rete memberships / desk
- **前提(Given)**: 松本は在庫精度改善PJ にマスタ提供役で参加していたが、繁忙のため一時的に当 PJ から外れる。後日、マスタ整備フェーズで復帰する。
- **操作(When)**:
  - 佐藤が在庫精度改善PJ から松本の membership を remove。松本が desk で在庫精度改善PJ と配下 #入荷検品/#棚卸差異 を開こうとする。
  - 後日、佐藤が松本を在庫精度改善PJ へ再 upsert。松本が再度サイドバーを確認する。
- **期待結果(Then)**:
  - 脱退中：松本のサイドバーから在庫精度改善PJ と配下チャネルが消え、直接アクセスは 403。
  - 復帰後：在庫精度改善PJ と配下チャネルが再び可視化され、脱退中に他メンバーが追記したスレッドも含めて閲覧可能（履歴は保持されている）。
  - upsert は冪等のため、復帰時に重複 membership は作られない。
- **状態**: ⬜ ／ **仕様**: ✅(アサート可能) ／ 対応: S-SPC-04 / S-SPC-05

### P4-12 誤操作境界：唯一の Space ADMIN を退職ロックする

- **登場**: 高橋 健一（システム ADMIN・退職対象）／中村 彩（情シス担当・ADMIN 昇格前）
- **システム**: rete members / space
- **前提(Given)**: 高橋は情報システム室 ORG の唯一の ORG ADMIN かつテナントのシステム ADMIN。高橋が退職するが、まだ中村への管理者交代（P5）を済ませていない状態で、誤って先に高橋をロックしようとする。
- **操作(When)**: オペレーターが高橋のアカウントを isActive=false にする、または高橋を情報システム室 ORG ADMIN から外す。
- **期待結果(Then)**:
  - ⚠ **最後の（唯一の）ADMIN を降格・ロックさせないガードが未記載**＝この操作がブロックされるか否かの正解像が無い。ガード不在なら、情報システム室 ORG が ADMIN 不在になり配下 PJ/チャネルの管理ができなくなる、あるいはテナントがシステム ADMIN ゼロになり復旧が seed/DB 直編集依存になる（ADR 上の保護要件が未定義）。
  - ⚠ 本シナリオは P5-1（管理者交代）と表裏。交代を先に行えば回避できるが、**順序を誤った時の安全網が無い**点が論点。
- **状態**: ⬜ ／ **仕様**: ⚠(未確定: 最後の ADMIN を降格/ロックさせないガードが未記載＝管理者全消失のリスク)
